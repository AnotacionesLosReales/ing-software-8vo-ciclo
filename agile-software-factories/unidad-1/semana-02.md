# Semana 2: Integration in Software Factories

## DevOps

### Intro

Es un conjunto de prácticas que trabaja para automatizar e integrar los procesos entre el desarrollo de software y los equipos de TI, para que puedan construir, probar y lanzar software de manera más rápida y confiable. 
El término DevOps se formó combinando las palabras "desarrollo" y "operaciones"

#### Principales elementos de DevOps

- Implementación de una cultura sin culpabilidad.
- Proporcionar aplicaciones y servicios Just-in-Time.
- Asegurar la calidad de los servicios TI.
- Gestionar el ciclo de vida de las aplicaciones y servicios.

#### Ventajas

- Velocidad.
- Entrega rápida.
- Confiabilidad.
- Escalabilidad.
- Colaboración mejorada.
- Seguridad.

#### Prácticas de DevOps

- Integración Continua (Continuous Integration).
- Entrega Continua (Continuous Delivery).
- Microservicios.
- Infraestructura como código (IaaC).
- Monitoreo y registro continuo (Continuous Monitoring).
- Comunicación y Colaboración.

### Marco CALMS para DevOps

- Cultura.
- Automatización.
- LEAN.
- Medición.
- Colaboración (Sharing).

### Integración Continua

El concepto de integración continua en DevOps hace referencia a la integración, construcción y prueba frecuente, preferiblemente de forma automatizada, del código que se entrega por si mismo y dentro del entorno en donde tiene que funcionar.

## Software Configuration Management

### Configuration Management

- Los cambios dentro del desarrollo del software pueden ocurrir en cualquier momento y se debe estar preparado, estas actividades sirven para:
  - Identificar el cambio de nuestro software.
  - Controlar ese cambio.
  - Garantizar que el cambio quede bien implantado.
  - Informar el cambio.
- La gestión de la configuración es el arte de identificar, organizar y controlar las modificaciones que sufre el software que construye un equipo de programación.

### Gestión del Cambio

- En la construcción de software los cambios son inevitable.
- Existen cuatro fuentes fundamentales:
  - Nuevos negocios o condiciones comerciales.
  - Nuevas necesidades del cliente.
  - Reorganización o crecimiento o reducción del negocio.
  - Restricciones presupuestables o de planificación.

### Control de Versiones

- Mantener múltiples versiones de archivos para permitir su seguimiento y siempre ser capaz de volver a la versión de trabajo funcional.
- Las prácticas DevOps dependen en gran medida de mantener un sistema de control de versiones.
- Las entregas rápidas aumentan la presión sobre el equipo de operaciones y sólo con el control de versión se puede asegurar el funcionamiento.
